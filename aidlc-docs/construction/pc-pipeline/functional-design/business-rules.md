# Business Rules — pc-pipeline

| ID | 규칙 | Story · AC |
| --- | --- | --- |
| BR-P01 | 대상 날짜 기본값 = 한국 시간 (Asia/Seoul) 기준 어제 | AC-16-1 |
| BR-P02 | Daily Papers 는 `limit=10` 으로 `p=0` 부터 받다가 10편 미만이 오면 멈춘다 (최대 20페이지). 네트워크 오류 · 429 · 5xx 는 최대 3회 시도 (대기 2초, 4초) | AC-16-1 |
| BR-P03 | 트렌딩은 모델 · 데이터셋 · Spaces 를 `trendingScore` 내림차순으로 설정 개수 (기본 10 · 5 · 5) 만큼 받는다 | AC-03-1 |
| BR-P04 | 키워드 규칙 분류: 주제별 단어 목록과 맞춘 점수 = 제목 일치 2점 + `ai_keywords` 일치 2점 + 초록 앞 600자 일치 1점. 최고점 주제, 동점은 주제 순서, 0점은 `other` | AC-17-1 |
| BR-P05 | 선별 점수 = 추천 수 + 30 (규칙 분류가 `focus_topics` 에 속함) + 15 (GitHub 있음). 점수 내림차순 → 추천 수 → id 순 상위 `max_featured` (기본 5) | AC-01-2 |
| BR-P06 | 키워드 = Hugging Face `ai_keywords` 를 소문자 · 공백 정리 · 중복 제거해 최대 8개 (제공자와 무관하게 같아야 트렌드가 흔들리지 않는다) | AC-09-3 |
| BR-P07 | `none` 결과: 한 줄 요약 = HF `ai_summary` (없으면 초록 첫 문장), 400자 자르기, `summary_source` = `hf` 또는 `abstract`. 주제 = BR-P04. 상세 요약 · 용어는 없음. 세 줄 = 주목 논문 상위 3편 "제목 — 한 줄 요약" (300자) | AC-17-1, AC-05-2 |
| BR-P08 | AI 결과: 모든 논문에 주제 · 한국어 한 줄 요약 (10편씩 묶어 요청), 주목 논문에 상세 4항목 · 용어 (최대 3개, 논문 본문 2만 자까지, 없으면 초록), 세 줄 요약. `summary_source` = `ai` | AC-05-1, AC-05-3 |
| BR-P09 | AI 호출 대상은 추천 수 상위 `max_ai_papers` (기본 60) 편까지, 나머지는 `none` 결과 | NFR-05 |
| BR-P10 | AI 응답은 JSON 으로 해석해 항목마다 형식 검사. 해석 실패 · 누락 · 형식 위반이면 1회 다시 요청, 그래도 실패한 항목만 `none` 결과로 대체하고 대체 수를 기록 | AC-17-2 |
| BR-P11 | 키가 필요한 제공자 (anthropic · openai · gemini) 에 키가 없거나, `cli` 에 명령이 없거나, `none` 이 아닌데 모델 이름이 없으면 수집 전에 무엇이 없는지 출력하고 종료 코드 3. 서버 주소 · 토큰 검사는 업로드하는 실행에만 (`--dry-run` 은 제외) | AC-17-3 |
| BR-P12 | 업로드는 Bearer 토큰. 네트워크 오류 · 5xx 는 3회 시도, 401 · 422 는 바로 실패 (종료 코드 2) | AC-19-1 |
| BR-P13 | 업로드 성공 시 상태 파일의 `last_success_date` 를 그 날짜로 (더 늦은 날짜만) 갱신 | AC-18-1 |
| BR-P14 | 빠진 날 채우기: 상태가 있으면 `last_success_date + 1` 부터 대상 날짜까지, 최근 7일만 오래된 순으로. 상태가 없으면 대상 날짜만. `--date` 를 주면 그 날짜만 | AC-18-1, AC-18-2 |
| BR-P15 | 논문 0편인 날은 세 줄 없이 Hub 트렌드만 올리고 성공 | AC-16-3 |
| BR-P16 | 실행 기록 (JSON Lines) 한 줄: `ts, date, status (ok/failed), stage, papers, featured, provider, ai_fallbacks, duration_s, error`. 토큰 · 키는 기록하지 않음 | AC-16-2 |
| BR-P17 | 리포트: 실행일 (한국 시간) 이 월요일이면 지난 ISO 주, 1일이면 지난달. 서버 통계를 받아 (404 면 건너뜀) AI 해석 3~5문장, `none` 이면 규칙 문장 (논문 수 · 상위 주제 2개 · 급상승 키워드 3개) 을 올린다 | AC-20-1, AC-20-2 |
| BR-P18 | 하루 처리 중 어느 단계든 실패하면 그 날짜는 업로드하지 않고 실패로 기록, 다음 날짜는 계속 시도하지 않는다 (순서 보장) | NFR-03 |
| BR-P19 | `radar backfill --days N` (1~120, 기본 90): 대상은 `--until` (기본 한국 시간 어제) 까지 N 일, 오래된 순 | 실데이터 요청 (2026-11-17) |
| BR-P20 | 1단계: 날짜마다 원본 보관본이 있으면 쓰고 없으면 수집 (새로 받은 날 사이 0.5초 쉼), AI 없이 분석해 바로 업로드. Hub 트렌딩은 "지금" 목록이므로 마지막 날에만 붙인다. 이미 AI 로 분석된 날은 건너뛴다. 하루 수집 실패는 기록하고 다음 날로, 업로드 실패는 전체 중단. 모든 날이 성공하면 `last_success_date` 갱신 | 같음 |
| BR-P21 | 2단계 (AI 제공자가 있을 때): 최근 날부터, `analyzed.json` 에 같은 제공자로 기록된 날은 건너뛰고 분석 · 업로드 · 기록. 한 날짜의 AI 작업이 모두 실패하면 제공자 문제로 보고 2단계를 멈춘다 (리포트는 계속) | 같음 |
| BR-P22 | 3단계: 범위에 걸친 모든 ISO 주 · 달의 통계를 받아 해석 문장을 올린다 (통계 없음은 건너뜀) | 같음 |
| BR-P23 | 서버가 429 를 계속 주면 `Retry-After` (최대 120초) 만큼 기다렸다 최대 3번 다시 보낸다 | 백필 시험에서 발견 |
