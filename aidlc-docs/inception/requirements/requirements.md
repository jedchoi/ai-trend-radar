# 요구사항 (Requirements)

## 의도 분석 (Intent Analysis)

- **요청**: 매일 Hugging Face 의 AI 논문 · Hub 트렌드를 수집해 요약하고 트렌드를 분석하는 시스템. PC 가 수집 · AI 분석을 하고, 결과를 backend 서버에 저장하며, 모바일 앱이 서버에서 당겨와 보여준다
- **사용자 목표**: AI 트렌드와 기술을 꾸준히 숙지하고, 현업에 필요한 기술 · 논문을 언제든 찾아 확인 · 적용
- **요청 유형**: 새 시스템 (Greenfield), 3개 구성요소
- **범위**: 다중 컴포넌트 (PC 파이프라인, backend 서버, 모바일 앱)
- **복잡도**: 보통 (Moderate)
- **깊이**: Standard
- **입력 문서**: 기획서 "AI 뉴스 요약 및 트렌드 분석 기획서" (claude.ai 문서), 확인 질문 답변 (`requirement-verification-questions.md`, 사용자 위임)

## 기능 요구사항 (Functional Requirements)

### PC 파이프라인

| ID | 요구사항 | 근거 |
| --- | --- | --- |
| FR-01 | 하루 한 번, 대상 날짜의 Daily Papers 전체를 10편 단위 페이지로 수집하고, 트렌딩 모델 10개 · 데이터셋 5개 · Spaces 5개를 수집한다 | 기획서 데이터 소스, Q5 |
| FR-02 | 규칙 기반 점수 (LLM · 에이전트 주제 가중, 추천 수, 코드 공개) 로 주목 논문을 하루 최대 5편 고른다 | 기획서 선별 기준 |
| FR-03 | 모든 논문에 고정 주제 분류 9개 중 하나와 한국어 한 줄 요약을 붙이고, 주목 논문에는 상세 요약 (무엇을 했나 · 새로운 점 · 왜 중요한가 · 실무 적용) 과 용어 카드 (최대 3개) 를 붙이며, 그날의 세 줄 요약을 만든다 | 기획서 일일 요약 형식, Q4, Q6 |
| FR-04 | AI 제공자를 설정으로 고른다: `none`, `anthropic`, `openai` (OpenAI 호환 주소 포함), `gemini`, `ollama` | Q1 |
| FR-05 | AI 응답을 스키마로 검사하고, 어긋나면 1회 다시 요청한 뒤에도 어긋나면 그 항목은 `none` 결과로 대체한다 | 기획서 위험 요소 |
| FR-06 | 분석 결과를 서버 업로드 API 에 날짜 단위로 올린다. 같은 날짜를 다시 올리면 덮어쓴다 (멱등) | 사용자 요구 (별도 서버 저장) |
| FR-07 | 마지막 성공일 이후 빠진 날짜를 최대 7일까지 순서대로 채운다 | 기획서 위험 요소 (PC 꺼짐) |
| FR-08 | 월요일에는 지난주, 매월 1일에는 지난달의 서버 통계를 받아 AI 해석 문장 (3~5문장) 을 붙여 리포트로 올린다 | 기획서 트렌드 분석 설계 |
| FR-09 | 실행마다 날짜, 수집 건수, AI 제공자, 소요 시간, 실패 단계를 실행 기록 파일 (JSON Lines) 에 남긴다 | 기획서 매일 실행 흐름 |

## 비기능 요구사항 (Non-Functional Requirements)

| ID | 요구사항 | 측정 기준 |
| --- | --- | --- |
| NFR-01 | 이식성: AI 는 파이프라인 분석 단계에서만 쓴다 | 제공자 변경 = 설정 파일 `provider` 1줄. `none` 으로 키 없이 전체 흐름 통과 (자동 테스트) |
| NFR-02 | 응답 성능 | 논문 10,000건 기준 조회 · 검색 · 트렌드 API p95 300 ms 이하 (로컬 측정) |
| NFR-03 | 실패 격리 | 수집 · 분석 · 검사 실패 시 업로드하지 않음. 업로드는 날짜 단위 트랜잭션 (부분 저장 0건) |
| NFR-04 | 보안 | 업로드 토큰 32바이트 이상 무작위, HTTPS 경유, 공개 API 는 읽기 전용 · IP 당 분당 120회 제한, 입력 길이 · 형식 검사, 비밀은 환경 변수 · 파일 (저장소 밖), 오류 응답에 내부 정보 없음 |
| NFR-05 | 비용 상한 | AI 호출 대상 논문 하루 최대 60편 (`max_ai_papers`, 초과분은 `none` 결과). `none` 은 비용 0 |
| NFR-06 | 테스트 | server · pipeline 각각 라인 커버리지 80% 이상. 앱은 모델 파싱 · 정렬 · 저장 로직 단위 테스트와 화면 위젯 테스트 |
| NFR-07 | 호환성 | API 경로 `/api/v1`, 응답 필드는 추가만 허용. 앱은 모르는 필드를 무시하고 없는 선택 필드를 허용 |
| NFR-08 | 실행 시간 | `none` 기준 하루치 처리 2분 이내 (수집 제외), AI 사용 시 15분 이내 |
| NFR-09 | 언어 | 요약 · 설명은 한국어, 논문 제목 · 모델 이름은 원문 |
